## 1. Purpose

`EWO-026.1` established the Foundation Layer's initial re-export list and proved two of its capabilities (full actor lifecycle with durable recovery; capability-denial enforcement) genuinely reachable. This work order completes the Foundation Layer to `ARCH-014` §5, item 1's own full standard: an exhaustive, individually-justified audit of every `pub` item in every dependency crate and every `Runtime` method's own signature — not a re-derived or assumed list — confirming the "no capability lost" claim is deliberate rather than accidental; test coverage extended to the three Developer Capabilities `EWO-026.1`'s own suite left untested (timers, direct capability issuance, Effects); and, following an Engineering Amendment, a repository-verified demonstration of the Foundation Layer's own literal Primary Objective, `use synapse_sdk::foundation::*;`.

---

## 2. Architectural Authority

- `foundation.rs`'s per-crate re-export blocks, each immediately followed by an individually-justified exclusion comment, directly implement `ARCH-014` §5, item 1's "adds nothing and removes nothing" standard as a checked, not assumed, property.
- The exclusion basis applied uniformly to `CapabilityAuthority`/`CapabilityAuthorityHandle`, `Timer`/`TimerHandle`, and `EffectCoordinator`/`EffectCoordinatorHandle` — each the replaceable-service substitution contract for a Trusted Core component, an Extension Layer concern (`ARCH-014` §5, item 4; §13) — is the identical basis `EWO-026.1` already established for `TrustedCore` itself.
- `StorageBackend`'s own inclusion, unlike the three exclusions above, rests on `ARCH-011`/`ARCH-012`/`ADR-0018` together making a custom durable-storage backend an ordinary, foreseen part of working with persistence through this Runtime — distinct in kind from replacing a Trusted Core component.
- The `wildcard_import` test module directly verifies `ARCH-014`'s own Primary Objective as a repository fact, isolated in its own submodule so the glob import cannot interfere with any other test's named imports — preserving `foundation.rs`'s own documented reason for using named re-exports internally while still proving external glob-usability.

---

## 3. Objectives

1. Independently audit every `pub` item across all seven of `foundation.rs`'s dependency crates (`synapse-runtime`, `synapse-api`, `synapse-common`, `synapse-capability-authority`, `synapse-timer`, `synapse-effect-coordinator`, `synapse-persistence`) and every one of `Runtime`'s own 35 `pub fn` methods, individually, against the existing re-export list.
2. Record, for every excluded item, an individual, specific justification — not a blanket rule.
3. Extend `sdk/tests/skeleton.rs` with coverage for the three Developer Capabilities left untested by `EWO-026.1`: timer registration and cancellation, direct capability issuance (`issue_capability`/`bind_capability`, as distinct from a bootstrap-granted capability), and Effects (`request_effect`, dispatched and confirmed delivered).
4. Demonstrate, in the repository's own test suite, that `use synapse_sdk::foundation::*;` genuinely supports a representative developer workflow.

---

## 4. Non-Goals

This work order MUST NOT, and its implementation does not:

- populate `ergonomics`, `prelude`, or `extension` with any real convenience, curated re-export, or extension mechanism;
- redesign any Runtime, Persistence, Recovery, Scheduling, or Capability behavior (confirmed: no Runtime `.rs` source file appears in this work order's own diff, at any stage, independently re-verified by the Independent Engineering Re-Review);
- change the Foundation Layer's own re-export list in substance — the audit confirmed the list `EWO-026.1` already established was complete; this work order's `foundation.rs` diff is documentation-only, independently re-verified line-for-line against `a67d088`;
- introduce a Public API Architecture tier-marking mechanism — explicitly deferred by `ARCH-014` §21 itself.

## 6. Required Test Coverage

`sdk/tests/skeleton.rs`, three new tests added by this work order's own original implementation:

- `foundation_layer_supports_timer_registration_and_cancellation` — proves `register_timer`/`cancel_timer` genuinely reachable, and that cancelling an already-cancelled timer fails truthfully.
- `foundation_layer_supports_direct_capability_issuance` — proves `issue_capability`/`bind_capability` genuinely reachable and enforced, distinct from every other test's use of a bootstrap-granted capability.
- `foundation_layer_supports_requesting_and_dispatching_an_effect` — proves `request_effect` genuinely dispatches to a provider actor, not merely records an intent.

Plus, added by the Engineering Amendment resolving Finding F01:

- `wildcard_import::foundation_wildcard_import_supports_a_representative_developer_workflow` — the Foundation Layer's own Primary Objective (`use synapse_sdk::foundation::*;`), proven as a repository-verified fact via a genuine bootstrap → define → create → shutdown sequence, isolated in its own submodule.

## 7. Engineering Amendment Record — Finding F01

An Independent Engineering Review of the original implementation found one Minor finding: the Foundation Layer's own literal Primary Objective — `use synapse_sdk::foundation::*;` — was never empirically demonstrated inside the repository's own test suite, despite being independently verified true via an out-of-repository scratch build performed during the review itself.

**Resolution**, confined entirely to `sdk/tests/skeleton.rs`: exactly one new test added, in its own submodule (`wildcard_import`) so the glob import could not interfere with any other test's named imports. An Independent Engineering Re-Review independently re-derived the claim directly from the module's own source (not accepted from the Amendment Report), confirmed the two pre-existing Foundation Layer tests were byte-for-byte untouched, confirmed `foundation.rs`'s own diff carried zero functional or re-export-list change, and confirmed the full workspace test suite (1001 tests) passed unchanged, concluding `READY FOR FOUNDER IMPLEMENTATION APPROVAL`.
