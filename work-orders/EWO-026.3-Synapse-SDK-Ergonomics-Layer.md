## 1. Purpose

`EWO-026.2` completed and exhaustively verified the Foundation Layer. This work order populates the Ergonomics Layer — `ARCH-014` §5, item 2 — with exactly three functions, each addressing a specific, evidenced pattern of repeated construction ceremony observed across every existing Foundation Layer test: `message()`, `bootstrap_grant()`, and `define_and_create()`. Each is a pure, ordinary Rust function composing existing Foundation Layer operations with no hidden behavior, no new capability, and no Runtime-owned decision.

---

## 2. Architectural Authority

Every function traces directly to `ARCH-014` §5, item 2's own text: "This layer introduces no capability the Foundation Layer does not already have; every one of its conveniences must be describable as an ordered sequence of Foundation Layer calls with supplied defaults." Each function's own doc comment answers this work order's own four API Design Requirements in the code itself: developer benefit, Foundation insufficiency, Runtime-behavior preservation, and the exact Foundation composition it reduces to. A persistence-configuration composition and a capability issue-and-bind composition were both considered and deliberately deferred to a future, separately-reviewed work order, disclosed in the module's own doc comment.

---

## 3. Objectives

1. Implement `message()` — constructs a `Message` from its five structurally meaningful fields, filling the remaining eight with the value every existing Foundation Layer test already, universally supplied.
2. Implement `bootstrap_grant()` — composes `BootstrapGrantName::new` then `BootstrapGrant::new`, removing the manual `OperationSet` wrapping and double fallible-construction ceremony every existing test repeats.
3. Implement `define_and_create()` — composes `Runtime::define_actor` then `Runtime::create_actor_instance_with_behavior`, removing the manual `ActorId` threading every existing test performs.
4. Prove each function's result is semantically identical to its hand-built Foundation equivalent, and genuinely, behaviourally usable through ordinary Foundation operations — not merely structurally plausible.

---

## 4. Non-Goals

This work order MUST NOT, and its implementation does not:

- introduce any macro, builder, derive, or trait magic;
- populate `prelude` or `extension`;
- modify `foundation.rs` or any Runtime, Persistence, Recovery, Scheduling, or Capability behavior (confirmed: no Runtime `.rs` source file, and no `sdk/src/foundation.rs` change, appears anywhere in this work order's own diff, independently re-verified at every review stage);
- choose any value on the developer's behalf that carries authorization, ownership, timing, or retry significance;
- implement the deferred persistence-configuration or capability issue-and-bind compositions — left for a future, separately-authorized Engineering Work Order.

## 6. Required Test Coverage

`sdk/tests/ergonomics.rs`, three tests, each proving structural equivalence (via `Debug`-formatted comparison, since neither `Message` nor `BootstrapGrant` derives `PartialEq`) against a hand-built Foundation equivalent, plus genuine behavioral usability:

- `ergonomic_message_is_structurally_identical_to_its_hand_built_equivalent`
- `ergonomic_bootstrap_grant_is_structurally_identical_to_its_hand_built_equivalent`
- `define_and_create_produces_the_same_outcome_as_the_two_manual_foundation_calls` — proves liveness via genuine message delivery, then exactly-once termination.

---

## 7. Default Value Justification

Every value supplied automatically by `message()` was individually reviewed: `delivery_constraints`/`durability_classification`/`information_classification` (the sole existing value of each zero-field unit struct — no alternative exists); `causation`/`correlation`/`deadline` (`None`, matching 100% of existing test usage, freely overridable); `replay_protection` (`ReplayProtection::default()`, matching 100% of existing usage); `trace_id` (mechanically derived from `id`, purely diagnostic, uninterpreted by any Runtime component); `capability_transfer` (`None`, truthfully representing "no delegation," matching 100% of existing usage, freely overridable). No default hides a meaningful choice or acquires a capability the caller did not request.

---

## 8. Engineering Amendment Record — Finding F01

An Independent Engineering Review of the original implementation found one Minor finding: the comment block preceding the message-delivery proof in `define_and_create_produces_the_same_outcome_as_the_two_manual_foundation_calls` described the test as "successfully suspending and restoring" the instance — a proof approach that was considered during implementation, found illegal (`suspend_actor_instance` is only a legal call from within an actor's own `handle`, mid-execution; `Idle -> Suspended` is not a legal transition), and replaced with message-delivery-plus-termination — but the comment was never updated to match, leaving it stale and self-contradicted by a second, correct comment later in the same test.

**Resolution**, confined entirely to `sdk/tests/ergonomics.rs`: the stale comment corrected to accurately describe the test's actual two-part proof (message delivery, then exactly-once termination). No code logic, API signature, or default value changed. An Independent Engineering Re-Review independently re-derived the corrected comment's accuracy directly against the surrounding code (not accepted from the Amendment Report), confirmed zero regression, and confirmed the full workspace test suite (1001 tests) passed unchanged, concluding `READY FOR FOUNDER IMPLEMENTATION APPROVAL`.

One non-blocking Observation was also recorded (not an amendment-requiring finding): the module's own documentation justifies `causation`/`correlation`/`capability_transfer`/`deadline` together as one group, without giving `capability_transfer` — textually adjacent to capability-delegation semantics — its own, sharper, individually-reasoned justification. The underlying default value was independently confirmed safe and correct; this remains recorded for a future documentation pass, not acted on here per this work order's own explicit prohibition on resolving non-blocking observations.
