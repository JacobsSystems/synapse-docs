## 1. Purpose

`ARCH-017` establishes the Runtime Observation / Connectivity architecture but, before this work order, none of its projection substance existed in `synapse-runtime`. This work order implements the Runtime-internal evidence foundation only: a private `observation` module computing all seven `ARCH-017` §17 operations as pure, synchronous, read-only projections over already-authoritative Runtime state, plus the one narrow `LifecycleGuardian` accessor `GetActorDetail` requires. No transport, no IPC, no Observation Service, no SDK-facing client, and no `services/observation` crate of any kind is introduced — this module is the internal substrate a later, separately Founder-gated work order (`EWO-029.3`, once `EWO-029.2` selects a transport) will extract, wrap, or redesign.

---

## 2. Architectural Authority

Every structural decision in this work order traces directly to `ARCH-017`:

- The seven `pub(crate)` projection functions (`runtime_status`, `durable_actors`, `actor_detail`, `capabilities`, `effects`, `supervision`, `diagnostics`) realize exactly `ARCH-017` §17's closed operation set — no eighth operation, no generic dispatcher.
- `ObservationMeta{sequence, status}` and the four-state `ProjectionStatus` enum (`Complete`/`Partial`/`Unavailable`/`Unsupported`) directly implement `ARCH-017` §18 / `ROI-07` / `ROI-08`, inheriting `ARCH-016` §21's cross-cutting partial-data-disclosure rule unmodified.
- `EffectProjection`'s metadata-only field set, reading exclusively from `EffectCoordinator::{attempts_for_actor, effect_of, attempt_status, provider_of}`, directly implements `ROI-16` (effect payload content never transmitted).
- Placement as a Runtime-internal module (`mod observation;`, not `pub`, not a new `services/observation` crate) reflects the Independent Engineering Work Order Review's own placement-ambiguity finding, resolved in favor of Option A: no `services/*` crate in this workspace depends on `runtime`, so seeding an early crate would have inverted the dependency direction for no benefit at this stage.
- `LifecycleGuardian::current_state` (`core/lifecycle-guardian`) is added as a narrow, read-only, `pub(crate)`-delegated accessor — resolving the `ARCH-016` §17 / `EWO-028` §9.3 disclosed "requires exposure" gap exactly as `ARCH-017` §23's `GetActorDetail` projection requires, with no new authority, field visibility, or mutation path introduced.

---

## 3. Objectives

1. Implement all seven `ARCH-017` §17 projection operations as pure functions over `&Runtime`.
2. Add the minimum `LifecycleGuardian` surface (`current_state`) `GetActorDetail` requires, preserving that crate's sole authority over actor lifecycle state.
3. Represent freshness as non-temporal, per-process sequence metadata (`ARCH-017` §18), never a fabricated or mandatory Runtime-owned timestamp.
4. Ensure every projection's `ProjectionStatus` is truthful: `Complete` only when nothing relevant is known to be missing, `Partial` when structurally incomplete by design, `Unsupported` when no authoritative source exists at all — never fabricated or silently narrowed.
5. Prove the above through this module's own test suite (17 tests), exercised entirely from within the crate (`#[cfg(test)]`), since no external caller is authorized by this work order.

---

## 4. Non-Goals

This work order MUST NOT, and its implementation does not:

- create a Runtime Observation Service, transport, IPC, wire schema, session, or connection-management layer (`EWO-029.2`/`.3`'s own separate, later, Founder-gated scope);
- create a `services/observation` crate or any new crate of any kind;
- expose any SDK-facing observation client or public API surface (`EWO-029.4`'s own separate, later scope);
- select or evaluate Runtime Connectivity Transport technology;
- begin GUI or Control Centre engineering of any kind;
- introduce any external Cargo dependency (independently reconfirmed at every review stage: zero added);
- modify any authoritative component's own ownership of the state it projects — every function reads only, via `&Runtime`, never `&mut Runtime`.

## 6. Required Test Coverage

`runtime/src/observation.rs`'s own `#[cfg(test)] mod tests` — 17 tests, exercising all seven projection functions and the `OBSERVATION_SEQUENCE` freshness mechanism directly:

- `sequence_strictly_increases_across_calls` — freshness metadata is a genuine per-call ordering signal.
- `runtime_status_reports_the_actual_runtime_state`, `durable_actors_reflects_actual_known_actors`, `supervision_reports_unregistered_for_an_unknown_actor` — the three always-`Partial` operations faithfully mirror their authoritative sources.
- `actor_detail_is_a_complete_definitive_answer_for_an_actor_with_no_live_instance`, `actor_detail_reports_the_actual_lifecycle_state_of_a_live_instance` — `GetActorDetail`'s corrected `Complete`/`None` and `Complete`/`Some` semantics.
- `capabilities_is_empty_for_an_actor_with_no_bindings`, `capabilities_projects_every_currently_declared_field_of_a_real_binding`, `capabilities_projects_no_retry_constraint_as_none_not_a_fabricated_default` — `ListCapabilities`' full, truthful `Complete` projection.
- `effects_is_empty_for_an_actor_with_no_effect_activity`, `effects_projects_a_real_dispatched_attempt_completely`, `correlate_effect_attempts_marks_partial_and_preserves_the_attempt_on_a_correlation_gap`, `correlate_effect_attempts_reports_no_gap_when_every_attempt_correlates`, `effect_projection_field_set_is_exhaustively_metadata_only` — `ListEffects`' no-silent-drop, truthful-`Partial`-on-gap behavior and `ROI-16` payload exclusion.
- `diagnostics_accepts_no_actor_and_reports_unsupported`, `diagnostics_accepts_a_known_actor_and_reports_unsupported` — `GetDiagnostics`' approved input shape and honest `Unsupported` result.
- `projection_functions_take_shared_references_only` — compile-time proof of the read-only boundary.

`core/lifecycle-guardian/src/lib.rs` — 3 additional tests for `current_state`: reports `Idle` for an untracked instance, reports the actual post-transition state, and does not mutate state across repeated reads.

At the implementation commit, the full workspace suite passed unchanged: `cargo test --workspace --all-targets --all-features` — all suites `0 failed` (`synapse-runtime`: 428 passed; `synapse-lifecycle-guardian`: 35 passed); `cargo fmt --all -- --check` — clean; `cargo clippy --workspace --all-targets --all-features -- -D warnings` — clean.

## 8. Review Lineage

Concise traceability only; full reports were delivered inline, at each stage, against the `synapse-runtime` working tree — no separate `IIR-`/`NIRR-`-series document was independently filed, on the identical basis every `EWO-026.x` predecessor already established for itself.

1. **Independent Implementation Review** — found `IIR-029.1-F01` (Minor: `GetActorDetail` mislabeled a definitive no-live-instance answer as `Unavailable`), `IIR-029.1-F02` (Minor: `ListCapabilities` omitted the declared retry constraint while reporting `Complete`), `IIR-029.1-F03` (Minor: `ListEffects` could silently drop a correlation-gapped attempt while reporting `Complete`), `IIR-029.1-F04` (Major: `GetDiagnostics`' implemented shape did not match `ARCH-017` §17's approved input), and two Observations (`O01`: freshness documentation needed precision; `O02`: a payload test's own framing overstated what it mechanically proved).
2. **Narrow Implementation Correction** — corrected all four findings and incorporated both observations: `actor_detail()` now always `Complete`; `CapabilityProjection` gained `retry_max_total_attempts`; `effects()` now uses a pure, independently-testable `correlate_effect_attempts` helper that never drops an attempt and reports `Partial` on a genuine correlation gap; `diagnostics()` rewritten to the approved `Option<&ActorId>` input shape, always honestly `Unsupported`.
3. **Narrow Implementation Re-Review** — independently re-verified all four corrections from source and re-ran the full quality-gate suite; confirmed `F01`–`F04` resolved and `O01`/`O02` incorporated, but found one new, bounded, correction-induced Minor finding (`NIRR-029.1-F01`): the `ProjectionStatus::Unavailable` variant's own documentation still cited the exact scenario `F01`'s correction eliminated, contradicting `ActorDetailProjection`'s own corrected doc comment.
4. **Further Narrow Implementation Correction** — corrected exactly `NIRR-029.1-F01`: replaced the stale, self-contradicting example with a generic, truthful definition, disclosing that no current projection constructs this variant. Zero executable behavior changed.
5. **Final Single-Finding Further Narrow Implementation Re-Review** — independently re-verified the documentation correction from source, confirmed no residual contradiction, confirmed all four original findings and both observations remained preserved, and confirmed the full quality-gate suite unchanged. **Verdict: PASS.**
